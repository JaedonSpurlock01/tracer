# Enforce authorization at the server boundary

Tracer resolves the acting identity once per request through `resolveActor`, which combines the Better Auth session with the user's Organization membership, and gates Operator-only pages and the `/api/users` handler through `requireActiveOperator`. An Active Operator is a user whose User State is Active and whose membership role maps to Operator. Hidden navigation is a convenience for the Sidebar and never substitutes for this check; Operator-only pages respond with Not Found to any other identity and the API responds with 401 or 403.

Workspace reads go through `data/workspace-authorization.ts`. `requireActiveActor` admits any Active Operator or Client Viewer, and `createReadableWorkspaces` returns every Organization Workspace to an Operator but only directly granted Active or Archived Workspaces to a Client Viewer. The grant check runs in the same SQL query as the read on every request, so removing an Access Grant blocks the next page load or API read from an existing session. Every Workspace mutation and every Operator-only read, such as Flow, numbers, and settings, still requires an Active Operator. Ungranted Workspaces respond with Not Found rather than Forbidden so a Client Viewer cannot discover them.

Client Viewer provisioning, Access Grant changes, and role changes run in `/api/users` under the Organization user lock. A Client Viewer and its initial Access Grants are written in one transaction, and demotion to Client Viewer checks last Active Operator protection and Access Grants in the same transaction.
