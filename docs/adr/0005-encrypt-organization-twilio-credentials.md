# Encrypt Organization Twilio credentials behind a fetch-based client boundary

Tracer stores the Organization's Twilio API key secret in the `twilio_connection` table as AES-256-GCM ciphertext produced through WebCrypto with a 32-byte master key supplied by the `TWILIO_CREDENTIAL_MASTER_KEY` deployment secret. The Account SID and API Key SID remain readable identifiers. Connect and Rotate Key verify the credential against Twilio before anything is written, Test Connection records only a short failure description, and no application interface, log, or error response ever returns the secret or its ciphertext. Disconnect is a pure policy decision over the Active Workspace count, which stays zero until M6 introduces the Workspace table.

Twilio access goes through the small `TwilioClient` interface implemented with direct REST calls over `fetch`. The official SDK was deferred because it adds a large Node-oriented dependency to the Workers bundle for two read-only endpoints; domain and service code depend only on the interface, so the SDK can replace the REST implementation later without touching them. Number inventory accepts only `+1` numbers normalized to E.164 and does not distinguish United States from Canadian numbers, because Twilio's owned-number API returns no country and neither a maintained area-code table nor per-number Lookup calls were justified for the first release.
