# Keep Provider Credentials in one module with a visible Unreadable state

Tracer stores the Organization's Twilio, Cloudflare, and DataForSEO secrets as AES-256-GCM ciphertext under the `TWILIO_CREDENTIAL_MASTER_KEY` deployment secret, as ADR 0005 decided. Until 2026-10-24 each provider connection module carried its own copy of the lifecycle, and a secret that the current master key could not open surfaced only as a generic provider outage at the moment of use, while the Integrations page kept showing the connection as Connected. That is how Production ran for two days after the master key changed on 2026-10-23: Detach Number answered 502, every Site sync failed before its first write, and nothing on the page said why.

`data/provider-credential.ts` now owns the lifecycle. Sealing a secret also stores a fingerprint of the key that sealed it, the first twelve hex characters of the SHA-256 of the key, which tells keys apart and cannot recover one. Reading a connection compares the stored fingerprint with the current key before touching the ciphertext, so each connection record carries a Credential State: readable or unreadable. An unreadable credential refuses every use with `credential_unreadable`, is recorded on the connection as its last failure the first time it is used, and the provider's health reads Needs re-entry ahead of connected or degraded. A missing master key stays `master_key_missing`, a deployment error no Operator action fixes. The three connection modules are adapters over this module: they know their columns, how to verify a credential with their provider, and nothing about keys.

Recovery is the Operator's: Re-enter credential is the existing rotate form, which verifies the new secret with the provider and seals it under the current key without reading the old one, and Disconnect removes the connection. ADR 0005 made Twilio Disconnect a pure policy decision over the Active Workspace count; that decision now takes a second input. When Active Workspaces depend on Twilio, the Operator may Disconnect anyway after acknowledging that every open Number Assignment ends without its Twilio voice configuration being restored. The same applies to Detach Number on an unreadable credential. Each such Number Assignment records the skipped restore, and the Workspace names the number until it is attached again, so the Operator knows what to clear in the Twilio console. Disconnect also counts Active Workspaces on its own transaction client, because asking the pool for a second connection from inside the transaction deadlocked under the one-connection pool Production ran with.

Numbers that a Number Assignment ever referenced are released rather than deleted on disconnect, so assignment history keeps its number and a later sync restores them.
